# SOURCES — Episode 3, "Tools: Giving a Model Hands"

## Primary source

**`tools.py`** — authored for this episode, shipped in this folder, runnable with no
dependencies and no API key.

- `to_schema()` is the function reproduced in beat **B05**. It was not transcribed: the
  beat sheet's `code` prop was generated by `inspect.getsource(tools.to_schema)` at
  authoring time, so the beat and the file cannot drift apart.
- `wire_view()` prints the payload shown in beat **B03**. It wraps and elides the
  description *and prints its true length*, so the abridgement on screen is the program's,
  not the editor's.
- `vague_read_file()` / `read_file()` are the A/B pair in beat **B07** — same body, two
  docstrings. The bodies are genuinely identical and the program checks it.
- `audit()` is a **keyword heuristic, not a linter**, and says so in its own docstring. It
  exists to show that a three-word docstring answers none of the three questions.

The full JSON payload (`json.dumps(to_schema(read_file), indent=2)`) is also printed by the

at video scale. Both come from the same `to_schema()` call.

## Continuity with Episodes 1 and 2

`tools.py` carries forward the same two tools — `read_file` and `count_rows` — that
`agent_loop.py` (Ep 1) and `trace_loop.py` (Ep 2) call. **The functions are unchanged.** The
only thing this episode adds is what is written *above* them, which is precisely the
argument: the code was always fine, the contract was the missing part.

It also pays a small debt. Ep 2 established that "the error IS the observation"; the
docstring for `read_file` in this episode now *says* that to the model — "a missing file
raises FileNotFoundError, and that error is the observation." The lesson from last week is
now part of the contract.

## Nothing else is cited, deliberately

No model, vendor, product, API, benchmark or price is named. The payload is described in
generic terms (name / description / parameter schema) so the episode does not date when a
provider renames a field. See `FACTCHECK.md`.

## Register rewrite (DOUBLE-CHECK LAW)

No prose source to parrot. The argument — *the description is the tool, and the cost of a
tool is paid on every call* — is the fellow's framing. The Teardown register earns its place
at B01 ("the bug is in the sentence above it"), B06 (a two-tool collision is a description
problem, not a model problem) and B08, where the design is charged for rather than praised.
