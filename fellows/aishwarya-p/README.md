## Research and results

This folder covers three bodies of work, in the order they were started.

### Mycroft Patent Reader

A system that reads a patent's claims section (the legal statements of what a patent protects) rather than its abstract, and traces the patent's citation lineage. It uses real data from Google's public patent dataset in BigQuery.

- **The design started as two agents with an honest stop.** The first version raised `NotImplementedError`, with a reason attached, rather than parse a data schema it hadn't seen yet. The data source then moved from the USPTO Open Data Portal to PatentsView to BigQuery.
- **The claims splitter was checked by hand.**
  - On US-11791319-B2 (20 claims: 3 independent, 17 dependent, with dependency chains three levels deep), every claim was classified correctly.
  - On 3 more patents and 44 more claims, every independent claim and dependency chain was also correct.
  - A multi-dependency flag turned out to be a false alarm, and the detector was narrowed.
- **The real cost of a query was measured, not assumed.**
  - The free tier ran out after nine test runs.
  - One exact-match lookup scanned 116.58 GB, about seventy cents at $6.25 per terabyte, and a repeat of the same query was free from cache.
  - A cheaper-looking table was rejected because it was last updated in 2017.
- **Scope classification uses judgment, not a rule.** Across nine independent claims (47 to 303 words long), word count and limitation markers didn't predict scope, so each claim is classified with Claude. A real refusal on a plant-cell-culture patent is caught and reported as "unclear", with the reason.
- **Broader testing found a silent parsing bug.** One patent wrote its claim numbers as `"1 ."` instead of `"1."`, so the parser returned zero claims for a patent with 14. It was fixed and checked against both formats.
  - Eight independent claims across four patents in four domains then classified with zero refusals.
  - Every one of those readings came back narrow and defensive, which was left as an open question.
- **The Lineage Agent reads backward citations** from the same row as the claims.
  - A real bug was caught: BigQuery returns empty strings, not missing values. On the first patent, 12 citations split into 1 patent and 11 papers, verified by hand.
  - On OpenAI's patent, 20 citations (18 of them patents) included Chinese and WIPO numbers, and all were parsed correctly.
  - Forward citations were deferred.
- **From CLI to API to a browser.**
  - The two agents were wired together, then put behind a FastAPI endpoint that calls the same agents.
  - A file lost in a rebase was recreated, committed, and re-verified on the same two patents.
  - A React frontend was added. The API key now loads from `.env` through `load_dotenv()`, which the code had never called before.
- **The frontend was hardened:**
  - three distinct error messages;
  - a loading spinner;
  - inputs disabled during a fetch;
  - classification off by default, so the free path is the default.
- **The classifier was measured.**
  - An evaluation harness scores it with accuracy, Cohen's kappa, a majority baseline and a collapse check.
  - One query (161.8 GB, about $0.92 at list price) pulled 160 candidate patents, and 147 of them have only 1-3 independent claims. The test set became 50 claims from 16 patents. See [Video 11](./2026-10-28-patent-agent-video11-classifier-eval-harness/README.md).
- **The first baseline.** All 50 claims were labelled by hand and the classifier was run once (cost upper bound $0.32).
  - Breadth: accuracy 0.66, kappa 0.08, against 0.92 for always answering "narrow".
  - Posture: accuracy 0.60, kappa 0.00, against 1.00 for always answering "defensive".
  - It leaned broad/offensive on functional claim wording: 10 of its 11 broad/offensive predictions were labelled narrow.
  - All 50 posture labels are defensive, so this set can't yet measure posture.
  - A refusal-handling bug in `claim_classifier.py` was fixed so all 50 claims score. The prompt fix has not started. See [Video 12](./2026-10-29-patent-agent-video12-baseline-results/README.md).
  - The evaluation harness and baseline run are committed to the mycroft repo ([3bcf1b1](https://github.com/nikbearbrown/mycroft/commit/3bcf1b1)).
