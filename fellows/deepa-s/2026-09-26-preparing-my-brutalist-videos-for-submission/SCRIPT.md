## Reviewing the video pairs

Each video now has two native versions: a sixteen-by-nine landscape cut and a nine-by-sixteen portrait cut. Portrait is composed independently for the taller frame; it is not just the landscape image trimmed down.

## Human review gates

That pair moves through two human review gates. I listen to and approve the narration before video rendering. Then, once both complete cuts are ready, I watch them before approving the finished pair.

## Quality control

Automation helps check technical details along the way. Depending on the project, checks can include output resolution, frames and layout, typography, safe areas, audio and loudness, complete decoding, and master-file properties. These checks support review; they do not replace it.

## Submission folders

I have also been building an organized local submission folder, with a separate folder for each content piece. Inside, Video is for the approved MP4s; GitHub is for Markdown documentation and the landscape and portrait Beat Sheets.

## Keep files in the right place

That separation gives each file a clear place and keeps video masters out of the documentation folder. The Beat Sheet stays with the written project material, where it describes the planned beats for each format.

## Verify the package

Before calling a copy ready, I can check that there are two MP4s, one landscape and one portrait, that both Beat Sheets and the relevant documentation are present, and that the GitHub folder contains no video files.

## File integrity

For file integrity, I compared SHA-256 hashes on the latest copied video pair. A file hash is like a fingerprint; matching values help confirm that the copy matches its approved source.

## A concrete check

Doing this for the latest pair made the verification step concrete. I checked the names and counts in each folder, confirmed both Beat Sheets, and matched each copied MP4’s hash against the source.

## What I learned

The broader lesson is that finishing a media project takes more than generating pictures and sound. It also takes review, quality control, clear organization, useful documentation, and checks that the right files made it into the right places.
