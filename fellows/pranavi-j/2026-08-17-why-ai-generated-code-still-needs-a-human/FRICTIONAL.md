# Frictional log — Why AI-Generated Code Still Needs a Human Who Understands the System

*Reconstructed 2026-10-20 from this folder's BUILD-LOG.md and FACTCHECK.md.*

## What was tried and expected

This was Film 1 of a new general-AI-topic series, teaching a reusable 3-question rubric (Trace / Consequence / Why) for scrutinizing AI-suggested code fixes, applied to a worked example (hand-escaped SQL insert vs. a parameterized-query fix). A real matching bug/fix existed in the fellow's own Project 29 (`mycroft`) engineering work, but the fellow deliberately chose a generic, illustrative version instead — both because the sibling weekly-report video had already reserved the real fix for a future episode, and to keep this general-AI-topic film independent of project-specific reporting. The plan was a 6-beat, then 7-beat (after adding a sign-off), ~2-minute explainer, with Gate P narration sign-off before any audio generation.

## Where it resisted

- A markdown formatting mismatch blocked the toolkit's own Gate P check: the sign-off line read `VERDICT: **PASS**` (bold) but the gate looks for the literal string `VERDICT: PASS` — fixed by reformatting to plain text without changing the fellow's actual decision.
- Several rounds of GATE A false positives from the static checker's render-free stub: a `SurroundingRectangle` wrapping text was silently excluded from shape-distinctness tracking (false "repeated animation" error), and bundling multi-step reveals into single `self.play()` calls left only one recorded shape-state. Both were fixed with real staggered reveals or by building highlight shapes from measured bounds instead of passing the mobject directly.
- GATE B caught real post-render margin issues (text overrunning the safe area, a divider line crossing a header) that were fixed in `scenes.py`.
- GATE V's automated pass reliably false-flagged every frame against the watermarked `-slate.mp4` review cut; every real check had to target the true clean master directly. That direct check still caught one genuine bug: B05's closing line was captured mid-`Write()` as jumbled glyphs because the reveal landed too close to the sample point — fixed by switching to `FadeIn()` and tightening timing.
- After the fellow watched the v1 master, she flagged it as too vague (beats named items without explaining them) and asked for real explanatory depth — a substantive content rewrite, not a bug fix, that nearly tripled the runtime (56s → 119s), which she explicitly accepted ("its okay if its longer add it").
- The v2 rewrite introduced new real defects: GATE A false positives again from bundled reveals, GATE B margin violations from longer multi-line captions, and two new genuine GATE V underfill findings because content now streamed in one row at a time and the closing punchline landed too late to ever be sampled — fixed by revealing the full skeleton immediately and bottom-anchoring the closing line.
- The fellow's third review (v3) asked for a title card (none had existed) and flagged confusing jargon ("diff" didn't land) — straightforward fellow-driven requests, not defects found by tooling.
- Adding the silent title-card beat required resolving a real open question about how the compile pipeline handles beats with no narration: tracing `compile.py` showed that a `null`/missing `audio_file` on even one beat drops narration for the *entire film*, not just that beat — resolved by generating a real silent mp3 rather than using `audio_file: null`.
- Renumbering beats (twice, for the title card and later the exec-summary beat) created a real risk of stale beat-ID-keyed clips silently filling new slots under the toolkit's skip-if-rendered logic — avoided each time by explicitly clearing stale `manim/*.mp4`/`clips/*.mp4` before re-rendering.
- A genuine visual bug surfaced only when the fellow herself watched the v3 master in a browser: a split-screen divider crossed through code text in B01's hook. Reproduced with real extracted frames, root-caused to a text block anchored by header position but never actually checked against the divider's fixed location, and fixed with a reusable `clear_of_divider()` helper that measures real rendered bounds rather than guessing.
- The v4 program-feedback rebuild hit a transient file-corruption issue (an output `.mp4` with no moov atom, traced to a race with a stalled prior process) and a major change in the toolkit's own `final_frame_check.py` (continuous frame sampling, MAJOR now blocking by default) that required re-establishing, via `--lenient` and direct frame inspection, that the real ship-blocking defect count was still zero.
- Building the 9:16 Short surfaced a latent bug in the shared toolkit's own `run.sh`/Manim invocation: `manim`'s `frame_width` is only derived once at startup from the quality preset's default resolution, before the CLI's `-r` override is applied — so every portrait scene silently rendered at roughly a third of its intended size. Fixed locally in `short/scenes.py`, flagged as worth fixing upstream but out of scope here.
- The Short build also found a real, pre-existing contrast defect in the shared palette itself (`teal`-on-`ink` measuring 1.56:1, far below WCAG's 3.0 floor) that the parent reel's own automated QC had never caught because its whole-frame average was diluted by other colors — fixed with a new high-contrast variant color, and a mislabeled auto-generated endcard handle (`@nikbearbrown` instead of `@HumanitariansAI`) caught by visual inspection, not by any gate.

## What Claude contributed, what was accepted/changed/rejected

Claude (via Claude Code) authored the beat sheet, all Manim scenes across four major revisions, generated and retuned Kokoro audio to match measured durations, ran and diagnosed every GATE A/B/V pass, found and fixed the false-positive watermark pattern repeatedly, and root-caused several real bugs (the divider-overlap defect, the portrait frame-width bug, the teal-on-ink contrast bug) through direct measurement rather than guesswork. The fellow drove every major content decision: she chose the generic worked example over the real Project 29 bug, approved the original 7-beat narration before any audio was generated (Gate P), then on three separate review passes personally caught real problems the automated checks had missed — vagueness in the explanation depth (v1→v2), missing title card and confusing jargon (v2→v3), and a visual divider-overlap bug she spotted by eye in a rendered frame (v3→v3.1) — each of which Claude then implemented and the fellow re-approved. The exec-summary beat's narration text was dictated by program feedback, not drafted by Claude.
