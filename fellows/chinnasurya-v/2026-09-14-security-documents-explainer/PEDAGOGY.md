# GATE P — Four Documents

**The one idea.** A security review is answered with four documents, and the
ones that say "no" are what make the other answers believable.

| Beat | The viewer should be able to say afterwards |
|---|---|
| B00 | this is about the paperwork behind a Canvas integration |
| B01 | one question produced four documents, each answering a different doubt |
| B02 | the security review states what is verified AND what was found wrong |
| B03 | the FERPA doc names the legal basis, every field, every subprocessor |
| B04 | the architecture doc gives measured backup numbers, not promises |
| B05 | HECVAT is a standard form — you don't choose the questions |
| B06 | no SOC 2, no pen test, MFA pending — and that is a good sign |
| B07 | one item is open, named in all four documents |
| B08 | the documents describe what was already true, or what got fixed |

**Register check.** Second person, plain English. Every acronym (FERPA, HECVAT,
RPO, WAL, SOC 2) is expanded or explained in the sentence that introduces it.

**Honesty check.** All 14 on-camera claims trace to one of the four source
documents; see `FACTCHECK.md`. No individual is named. No subprocessor is named
aloud. No hostname, no key material. Every measured figure was taken on the dev
environment, and the reel says so nowhere because it claims nothing about prod.

**Weakest beat.** B03. The FERPA document is the densest of the four and the
narration compresses three tables into four sentences; a viewer will retain the
shape (fields, stores, retention, subprocessors) rather than any specific row.
