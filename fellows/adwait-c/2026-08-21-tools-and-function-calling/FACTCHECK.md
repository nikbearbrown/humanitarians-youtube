## Corrections applied during authoring

- **B07's central claim was false, and was fixed in the code rather than softened in the
  script.** The draft said the two functions were "byte-for-byte identical" while
  `vague_read_file` actually delegated (`return read_file(path)`). Rather than weaken the
  line, `tools.py` was changed so the two bodies genuinely are identical, and the program now
  *asserts* it on screen (`function bodies identical: True`). The claim is now the strongest
  kind — a control the viewer can see.
- **"Nine lines" → "fourteen lines"** in B05, after counting the real source.
- **`audit()`'s first question renamed** from "what it does" to "what it returns". The
  heuristic marked `"Reads a file."` as failing, which was unfair under the old label — that
  string *does* say what it does. What it never says is what comes back, and that is now what
  the check claims to test.
- **Removed a model-behaviour claim.** An early B06 draft said a model "will pick the wrong
  tool" given two vague descriptions. Nothing in this build calls a model, so that would have
  been an assertion about behaviour we did not observe. The beat now makes the mechanistic
  point — disambiguation can only use what crosses the wire — and the "unsure" exercise is
  handed to the viewer in BHTF, where they can run it against a real model themselves.
- **No API field names presented as universal.** The payload is described in generic terms
  (name / description / parameter schema) so the episode does not date when any provider
  renames a field.

## Anti-dating audit

Searched the full narration and every prop string for model names, version numbers,
