MCP, Explained — what the Model Context Protocol actually is

A model on its own is sealed in a box. It can write text back to you and nothing else.
MCP is the standard plug that lets it reach outside that box — in a way you can read and
switch off.

This is a short, concrete walkthrough: the two sides and the gap between them, why one
shared protocol turns a hundred integrations into ten, and the four words you keep meeting
(host, client, server, tool).

No diagrams standing in for evidence. The config file is mine, on my laptop — two servers,
two different transports. The tool schema is real, and so is the call: one argument in,
five open browser tabs back. The model never browsed anything. It asked, the server looked,
the answer came back as data.

Ends with something to do: open whatever AI app you already use, find its MCP or connectors
settings, and just read the list of tools it has been given. Don't add anything. For each
one ask — do I understand what this is allowed to do.
