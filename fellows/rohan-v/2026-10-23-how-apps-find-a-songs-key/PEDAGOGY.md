# PEDAGOGY — "How Apps Find a Song's Key"

How the reel is built to teach someone who has seen a key label but never been told how it is found.

## The register

*No assumed knowledge* and *the viewer has to learn something*: the reel starts from a piano's white keys,
plants the one idea that explains the main failure (same notes, different home) before any mechanism, shows
each step on one real song, and ends on what to check when a label looks wrong.

## The shape

| Beat | Job | What the viewer can do after it |
|---|---|---|
| B00 ASK | the question: how does an app hear the key? | name the answer's shape: count, match, choose |
| B01 BACKGROUND | a key = seven notes + a home; C major and A minor share notes | spot two keys that share every note |
| B02 MECHANISM | chroma and the note profile, on a song they hear | say what the app actually measures |
| B03 MATH | matching the profile to 24 key shapes by correlation | explain why one key wins |
| B04 MEASURED | 60 songs, 50 right | trust the method where it works |
| B05 THE CATCH | natural-minor ballads read as their relative major | predict the most natural mistake |
| B06 KEY CHANGE | one label vs windows | know when one label can't be right |
| B07 WHAT TO DO | check the relative key; check sections | fix a wrong key in their own tools |
| B08 OUTRO | sign-off | — |

## Choices worth defending

- **B01 sets up B05.** The relative-key failure is predicted before it happens, so it lands as understanding.
- **A zoomed axis, printed.** B05's two bars are 0.005 apart; the axis range is on screen so the zoom isn't hidden.
- **Synthetic songs.** The true key of every song is known exactly, every number is reproducible, and no
  recordings enter a public repo.
