# FACTCHECK - How Consistent Hashing Scales Distributed Systems

| Claim | Source / Technical Standard | Verdict | Implementation Note |
|---|---|---|---|
| Modulo hashing (`hash(key) % N`) remaps nearly all keys when N changes | Karger et al., "Consistent Hashing and Random Trees" (ACM STOC 1997); Dynamo: Amazon's Highly Available Key-value Store (SOSP 2007) | TRUE | In standard modulo hashing, changing $N$ to $N \pm 1$ shifts almost every key's destination ($\approx (N-1)/N$ keys remapped), causing massive cache misses and database thundering herds. |
| Consistent hashing maps keys and servers onto a continuous circular hash ring | David Karger et al. (MIT 1997); Apache Cassandra Architecture; Ketama Memcached library | TRUE | Both data keys and server identifiers are hashed into the same numeric space (typically $[0, 2^{32}-1]$) visualized as a 360-degree continuous ring. |
| Keys route clockwise to the first encountered active server node | Amazon Dynamo Paper (DeCandia et al., 2007); Redis Cluster Specification | TRUE | Hashed key positions walk clockwise around the perimeter until the first node whose position is $\ge$ the key's position is reached (wrapping around at $2^{32}-1$). |
| Adding a node only remaps $K/N$ keys on average from its clockwise successor | Karger et al. (1997); Google Chubby & Spanner distributed storage systems | TRUE | Inserting a new server node claims only the arc between its predecessor and itself; only keys residing in that specific slice move, leaving all other $(N-1)$ servers untouched. |
| Removing or failing a server spills keys gracefully to the next clockwise neighbor | Amazon DynamoDB Design; Ketama Consistent Hashing Specification | TRUE | When a server dies or is removed, only its specific keys transfer to the immediate clockwise neighbor; no full-cluster rehash occurs. |
| Non-uniform distribution creates hotspots when server count is small | Stoica et al., "Chord: A Scalable Peer-to-peer Lookup Protocol" (IEEE/ACM ToN 2003) | TRUE | Random hash placement of few physical nodes produces unequal arc lengths, causing certain nodes to shoulder disproportionately heavy request loads. |
| Virtual nodes (vnodes) distribute traffic evenly across physical hardware | Amazon Dynamo (2007); Apache Cassandra Virtual Nodes Documentation | TRUE | By assigning multiple virtual tokens (typically 128–256) per physical server distributed uniformly around the ring, keys are divided into small, balanced partitions across all machines. |
| Consistent hashing powers petabyte-scale horizontal elasticity across major architectures | Discord Engineering (ScyllaDB/Cassandra scaling); Akamai CDN edge mapping; Amazon DynamoDB | TRUE | Consistent hashing is the foundational routing and partition protocol for global CDNs, distributed DHTs, distributed caches (Memcached Ketama), and Dynamo-style distributed databases. |
