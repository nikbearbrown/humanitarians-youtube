**On screen:** one concept -> many tags

**Narration:** Three filings, three different labels, all pointing at the same idea. Treat them as different and your comparison across companies is broken. Treat them as the same without checking and you might merge two things that only look alike. Either mistake is silent.

## Beat 5 — THE MECHANISM

**On screen:** resolve_metric — code

**Narration:** The fix is deliberate. For each metric, keep an ordered list of tags, most preferred first, the modern standard before the older ones. Take the first the company reports, and record which tag matched, on every value. So the mapping is visible and anyone can disagree. And when nothing matches, it doesn't guess. It flags the metric as missing.

## Beat 6 — THE LIMIT

**On screen:** Missing is not wrong

**Narration:** One nuance. When a company uses its own custom tag, that's not an error. It's often the most accurate label for something unusual. So missing doesn't mean bad data. It means the tool needs a human to confirm the mapping. That distinction keeps the dataset honest.

## Beat 7 — The verdict

**On screen:** Same name is not the same as same meaning

**Narration:** Any time you merge data from different sources, comparability is a decision, and you should be able to prove it. Do the labels truly mean the same thing? Which exact source did each value come from? Could someone audit that mapping later? And what did you refuse to merge? Numbers are never just numbers. The names matter.
