## Monthly format

Add a dated `YYYY-MM-DD-status.md` and matching evidence files; retain earlier snapshots. Each report should record its source commit, scope and limits; summarize every project family; distinguish education, operations, prototype, implementation and deployment; classify the work; verify publication claims; rank story opportunities with explicit evidence and release gates; and explain what changed since the last report.

Use first names and initials or repository folder IDs, not personal contact details. A missing artifact is an evidence gap, not proof of inactivity. Folder/file/video counts are not productivity scores. Explicit fictional examples are not real fellow achievements. Do not erase work, contact contributors or publish media as part of the monthly review unless separately authorized.

The dated source commit is authoritative for what was reviewed. Existing work may change after that snapshot. A build log or author's report is not an independently reproduced experiment; a demo is not a beneficiary-outcome study; a cited paper is not a fellow-authored publication.
