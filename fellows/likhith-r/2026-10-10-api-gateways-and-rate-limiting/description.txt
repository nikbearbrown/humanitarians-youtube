When many services sit behind one product, who stops a single client from overwhelming them? This explainer covers API gateways and rate limiting.

What's covered:
- Without a gateway, every service repeats its own auth, logging and overload protection
- An API gateway is one entry point that checks identity, routes and logs once
- Rate limiting caps requests per client and refuses the excess with 429
- A token bucket allows short bursts, then holds clients to a steady rate
- A sliding window fixes the fixed window's double-burst at the reset
- For AI APIs, per-user limits stop one client draining shared capacity

Sources: microservices.io API Gateway pattern, RFC 6585, RFC 2697, Cloudflare's rate-limiting write-up, Anthropic's rate-limit docs. All limits and traffic shown are illustrative.
