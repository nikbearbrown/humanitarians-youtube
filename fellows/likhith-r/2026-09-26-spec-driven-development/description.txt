Vibe coding feels magical — until a prompt-driven project grows past a few files and starts breaking in ways nobody can explain. This explainer covers spec-driven development: writing a clear spec of requirements and behavior before generating code, and treating that spec as the source of truth.

What's covered:
- Less guesswork: the model builds what you intended, not what it inferred
- Reviewability: check changes against the spec instead of reverse-engineering intent from a diff
- Living documentation: the spec is versioned with the code, so context survives sessions and teammates
- Scope drift: code that isn't in the spec stands out immediately

Source: Den Delimarsky, "Spec-driven development with AI", The GitHub Blog (2025-09-02), and github/spec-kit. Examples are illustrative; the closing curve is a qualitative sketch, not data.
