Brief supplied by the requester (Likhith), 8 points; each checked against the references below (2026-10-22).

## Corrections / de-sensationalising
- Brief point 6 ("does not auto-generate from raw documents like RAG can; someone has to curate it by hand"): **corrected.** Google's post and the spec say OKF files can be drafted and updated by agents (the reference agent drafts a concept doc per BigQuery table, then enriches it). The true cost is curation and review, by people or agents. Narration: "someone must curate it. People or agents write pages; someone reviews them." B07 shows both `human:` and agent authors, and the v0.2 `verified` / `stale_after` fields.
- Brief point 1: Google did not frame OKF as a RAG replacement; the post doesn't mention RAG. The reel frames the comparison as ours ("why something new?"), and the verdict calls them different approaches, not a winner.
- Brief point 3 "no embeddings or vector database required": kept as "not required". The spec allows a search index as one consumer; it just doesn't need one.
- Brief point 5 "no retrieval step": the agent still chooses what to open, via index files and links. Shown as a walk, not as "reads everything".
- Version: v0.1 was announced June 12, 2026; the spec is v0.2 now. The verdict says so ("v0.1 in June 2026, v0.2 since").
- The 2,000,000-doc count in B08 is illustrative and labelled that way on screen.
