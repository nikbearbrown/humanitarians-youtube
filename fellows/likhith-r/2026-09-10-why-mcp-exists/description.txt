APIs already let software talk to software — so why does MCP exist? This explainer covers the Model Context Protocol from an AI agent's point of view.

What's covered:
- Every API brings its own auth, request format and docs, so each agent needs custom code per tool
- MCP wraps a tool once as a server that any MCP agent can call the same way
- Agents discover tools at runtime (tools/list), shown from a real run of a toy MCP server
- The server still talks to the real API, auth included: MCP is a common language on top, not a replacement

Sources: Anthropic, "Introducing the Model Context Protocol" (2024), and the MCP specification. The terminal analogy and the tool names shown are illustrative.
