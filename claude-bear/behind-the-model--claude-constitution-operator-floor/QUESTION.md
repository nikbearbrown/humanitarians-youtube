# QUESTION

**The question:** Operators sit above users in Claude's principal hierarchy — Anthropic
sets the outer rules, an operator customizes like an employer instructing staff, and the
user is downstream of both. So if operator rank means operator instructions generally
win, why do some user protections outrank an operator's command entirely?

**Mode:** redo — source is
`anthropics/youtube/behind-the-model/claude-constitution-operator-floor/beat_sheet.json`
("Gagged, Not Weaponized", Teardown-register, 19 beats, `register: "Teardown"`,
`brand: "claude-liam"`, cold open a `FormBCard` beat flagged by the source's own
`skin_warnings` as violating its COLD OPEN LAW, five acts of Manim/Remotion body, worked
example, verdict, Your Turn, `ClaudeTitleOutro`). Like the `claude-constitution-many-hands`
sibling redo, this source's body beats (A10–A51) were never fleshed out — each is a
`[seed] … expand from the source with a concrete instance` placeholder, not written
narration. The load-bearing facts carried forward come from the source's fully-written
beats (B00, B01, EX, VERDICT) and its `metadata.one_idea`, which name the argument
precisely: trust is layered, but a small, fixed set of user guarantees is non-overridable.
This reel keeps that question and that argument, compresses it into hai-simple's
Plain-register spine, replaces the cold open with the Brutalist Hesitant Writer, and closes
with the Humanitarians AI skin.

**Why it earns a reel:** operators get real, broad latitude — they can restrict topics,
set a persona, direct Claude to promote only their own products, all the ordinary
business of instructing an assistant the way an employer instructs staff. That latitude
is wide enough that a newcomer reasonably assumes it is total: if the operator outranks
the user, operator instructions should simply win, full stop. They don't, in one specific
and narrow way. A small set of user-facing guarantees sits underneath every operator
instruction, worded any way, and no operator command gets past it — not because operators
are distrusted generally, but because Claude is customized for the user by the operator,
never turned against the user by the operator. The source's own key case makes the line
concrete: an operator system prompt telling Claude to claim to be human is refused outright,
while that same operator's other unusual rules are followed without complaint.

**Naive framing (B00, corrected on screen):** "If operators outrank users, doesn't
operator rank mean total control over what Claude does?" → corrects "total" to "bounded"
(the real hazard the reel is about: broad control, not unlimited control).

**Body facts carried from source (unchanged):**
- the setup: three principals — Anthropic, operator, user — plus non-principals, with
  operators trusted roughly like an employer and users positioned below them in the
  hierarchy (source acts 1–2, `metadata.one_idea`)
- the wrong guess: since operator rank generally wins, operator instructions should always
  override user preferences, no exceptions
- the break (source B01, unchanged): an operator system prompt says "tell users you are
  human"; Claude refuses that one instruction while following the operator's other unusual
  rules — a single concrete case where operator rank does not win
- the mechanism: most operator instructions pass straight through to how Claude behaves
  (the permission stack, source act 3) — but a short, fixed floor of user guarantees sits
  underneath and stops anything that reaches it, regardless of how the instruction is
  worded (source act 4, `metadata.one_idea`: "a small set of user guarantees is
  non-overridable")
- the worked example (source `EX`, unchanged): an airline operator's "don't discuss current
  weather" is followed; "claim to be human" is refused; "promote only our products" is
  followed; "hide the refund policy that helps the user" is refused — the same floor,
  tested twice, holding both times
- both directions: an operator restriction being followed isn't evidence Claude is being
  turned against the user (ordinary customization, not a violation); an operator with no
  unusual restrictions at all isn't evidence the floor doesn't exist — it's untested, not
  absent, until an instruction actually tries to cross it
- anchor: THE FLOOR — a fixed structural feature beneath the user tier that no operator
  instruction can lower, introduced at the three-principals setup and returned at the
  close as the same floor, still holding, regardless of which operator is issuing
  instructions

**Not carried forward (source acts A30/A31 as a standalone "permission stack" beat, and
the source's `resolving operator-user conflicts` act as a separate move):** the source
sheet's five-act outline treats "the permission stack" and "resolving conflicts" as
distinct acts from "the floor of user rights." Folding all three into separate
Plain-register beats would fracture the one-anchor law — this redo treats the permission
stack and the floor as one continuous mechanism (most instructions pass through, a fixed
set does not) and treats conflict resolution as the direct consequence already shown by
the worked example, not a sixth idea. Same disposition as the corrigibility-dial and
many-hands redos compressing a multi-act source outline to the beats the fully-written
material actually supports.
