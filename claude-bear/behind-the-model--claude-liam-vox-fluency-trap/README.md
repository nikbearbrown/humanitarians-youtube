## Title

A Polished Output Is Not Evidence the Work Is Correct — the Fluency Trap, Explained

## Description

Claude can hand back a citation, a claim, and a number in the same fluent paragraph, in
exactly the same confident voice. Nothing in how it reads tells you which parts were
checked and which were invented. So the natural read: if the writing is this polished and
organized, the sourcing underneath is probably solid too. Here's the case that breaks it —
a summary came back with precise phrasing and three careful citations, polished enough
that she opened all three. One paper didn't exist. One said the opposite of what the
summary claimed. One was from an unrelated field entirely.

Language models are trained to produce fluent, coherent, well organized text — that
training target is coherence, not accuracy, so the model gets very good at one thing:
sounding right. High-confidence prose is structurally uncorrelated with correctness; the
accurate paragraph and the invented one come from the exact same process. Even the
agent's own report isn't evidence — "I checked the sources" can mean it matched citation
text against memory, never opening a document.

From Humanitarians AI: short, plain explanations of how Claude actually works, for a
general audience meeting Claude for the first time. Liam, in for Professor Bear.

In this one: why polish doesn't predict accuracy; what training actually optimizes for;
the one flag worth knowing (a report is only a check if a tool actually opened the file);
a concrete case (Carlos's policy brief); and both directions — what running the source
checks proves, and what one bad citation does not prove about the rest of the document.

Try it yourself — the video ends with a paste-ready prompt for building your own
