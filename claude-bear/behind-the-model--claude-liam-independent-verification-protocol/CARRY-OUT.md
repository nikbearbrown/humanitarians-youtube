# CARRY-OUT — GATE C

Written before any other narration. Every beat exists to make this sentence survivable.

## The line

> **An agent's "verified" is a claim, not evidence — the artifact you name
> before the task starts is what makes it checkable.**

(Compressed from the source's B07 summary beat — "Verification is designed
before the agent starts. What you specify as the evidence artifact is what
makes the task verifiable instead of impressive" — restated in Plain register.
It states mechanism, not a design judgment, so nothing needed removing.)

## The wrong guess it defeats

That an agent's own "verified" is sufficient confirmation — it already did
the reasoning once, so a self-check should catch its own mistakes. That's
backwards: a citation matched against the agent's own training data instead
of the real document can pass that exact self-check, because the check runs
on the same process that produced the error in the first place. Evidence has
to come from outside the agent's own say-so, and it has to be named — output
type, independent evidence, the specific failure it checks, the artifact
that must exist — *before* the task starts, not improvised after.

## The secondhand test

*If someone repeats only this sentence in a meeting next week, is it still true?*

Yes — it compresses the one distinction that matters (a claim about the
work vs. an inspectable artifact) without claiming self-checks are worthless
or that every task needs the same kind of artifact.

## What it deliberately does not say

- Not a claim that agents can never be trusted to self-report — it's a claim
  about what counts as *independent* evidence, not a blanket suspicion.
- Not a claim that one artifact proves the whole task is correct — a checked
  artifact only proves what its specific check covers (direction A, B05).
- Not a claim that a different artifact on a different task is a verdict on
  the agent overall — the same four-field structure just gets reapplied with
  new fills (direction B, B06).
