## Description

When a FHIR request is invalid, does Claude just say pass or fail, or does
it name the exact problem?

This is Professor Bear's Claude-basics series, narrated by Liam. Today's
worked example is `fhir-developer-skill`, an Anthropic Claude Skill for
FHIR REST API development from a healthcare plugin. A Skill is a folder
Claude reads before it acts — one file, SKILL.md, written in plain
language, plus references and scripts folders: three items total. The
pipeline lives in SKILL.md's Steps section and runs linearly: read a step,
execute it, return the result — no branching unless a step itself says so.
The skill validates FHIR resources and returns the exact HTTP status code
for what's wrong — 422 for an invalid enum value, 412 for an ETag mismatch
on a conditional update. The status code is the spec: same input, same
code, every run.

Carry-out: fhir-developer-skill doesn't just pass or fail a request — it
returns the exact status code that names what's wrong, and that code is
the spec.
