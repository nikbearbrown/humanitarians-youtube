# CARRY-OUT — GATE C

Written before any other narration. Every beat exists to make this sentence survivable.

## The line

> **A skill isn't a built-in capability — it's a folder of plain-language
> instructions Claude reads before it acts, and follows exactly, only as far
> as the file goes.**

## The wrong guess it defeats

That a documented behavior like `first-run` is baked into the model — a hidden
"mode" Claude ships with. It isn't. `first-run` is one file, `SKILL.md`,
written in plain language; Claude reads it before acting and executes its
Steps section in order. The behavior is exactly as reliable, and exactly as
limited, as what that file says.

## The secondhand test

*If someone repeats only this sentence in a meeting next week, is it still true?*

Yes — it compresses the one distinction that matters (a skill is read text,
not a hardcoded feature) without smuggling in a claim about which skills are
well-written or a verdict on whether the skill format is a good design.

## What it deliberately does not say

- Not "skills can do anything" — the beat that precedes this one (B03) states
  plainly that first-run has nothing to say about a task its file never
  described.
- Not a verdict on whether the SKILL.md format is well-designed, or better/worse
  than an alternative — that would be a Teardown-register judgment ("gets right"
  / "bites"), which this redo explicitly removes from the source's B03/BVDT.
- Not a claim about every skill ever written — first-run is the specimen, not
  a universal proof.
