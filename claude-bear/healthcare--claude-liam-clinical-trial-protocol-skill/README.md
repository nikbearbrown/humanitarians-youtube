## Description

When Claude helps put together a clinical trial protocol, is it making the
trial-design calls itself, or just drafting the document to a fixed
specification a person still has to review?

This is Professor Bear's Claude-basics series, narrated by Liam. Today's
worked example is `clinical-trial-protocol-skill`, an Anthropic Claude Skill
from a healthcare plugin, used for requests like "create a clinical trial
protocol" or "help me design a clinical study." A Skill is a folder Claude
reads before it acts — one file, SKILL.md, written in plain language, plus a
README and folders for assets, references, and scripts: five files total.
The pipeline runs in three linear steps: read SKILL.md to load the
instructions, execute each step from the Steps section in order, then return
the result — no branching, unless a step itself says so. It follows the
SKILL.md's instructions exactly, so the same request produces the same kind
of protocol every run. What it won't do is anything outside what the file
specifies.

Carry-out: clinical-trial-protocol-skill drafts the protocol to a fixed
spec — it doesn't decide how the trial should run; that call still belongs
to a person.
