# Claude, Hiring Review.

Claude picked up a skill called hiring-review — does that mean it got
judgment about who to hire? No. A "skill" is a folder holding one file,
SKILL.md, that Claude reads before it starts and then follows step by step,
in order. Delete the folder and Claude loses no hiring judgment, because
there was none to begin with — it just stops following that one checklist.
That makes a skill a specification, not new judgment: the payoff is the
same checklist, every review, every time; the limit is anything the file
never wrote down. And watching Claude flag every risk, or flag nothing,
proves nothing on its own about whether the hire is actually clean.

## Deliberately not claimed

This reel does not describe what the hiring-review skill's own SKILL.md
specifically instructs — that file lives in an employment-legal collection
not reachable from this build, and the source script this reel redoes never
filled in that detail either (its own beat sheet still carries an unfilled
`>` placeholder in three spots). Rather than invent an employment-law-
specific procedure, this reel uses "hiring-review" only as the named
example of a skill-shaped folder (one file, SKILL.md, walking through a
hiring decision step by step), and sticks to what's true and generic about
how any Claude skill works: a folder Claude reads before it acts, executed
step by step, with a payoff and a limit. See BUILD-LOG.md for the full
account.
