# The File Is the Program. — The Skill Development Skill

A skill is a folder Claude reads before it works — no code, no hidden logic.
Inside: a SKILL.md file (plain-language instructions) and a references
folder. Two things decide what happens: the description states when the
skill applies (for skill-development, that's wanting to create a skill, add
one to a plugin, write a new one, improve a description, organize content,
or get guidance on skill structure), and once a request matches, Claude
executes the Steps section top to bottom, linear, no branching unless a
step says so. Because it's plain instructions and not code, it runs the
same way on the same request every time — but nothing hidden covers what
the file doesn't say. Ask for something outside the SKILL.md, and there's
no fallback logic underneath to catch you.

## Deliberately not claimed

No claim about how Claude's underlying dispatch mechanism matches a
request against a description (pattern-match vs. model judgment) — the
source Skill's SKILL.md doesn't document that internal mechanism, and this
video doesn't guess. No claim that every Claude Skill is structured
identically to skill-development's own two-item layout (SKILL.md plus one
references folder); that's this specific skill's file count, not a claim
about Skill folders in general.
