**The line (written first, GATE C):**

> A Claude data analysis isn't an analyst's feel for what's interesting —
> it's a written procedure that matches your question to one of four
> shapes and runs the same steps every time, and it only covers question
> shapes the file defines.

**Test:** if someone repeats only this in a meeting next week, is it still
true? Yes — it compresses the one distinction the reel is built to land (a
tailored, written procedure vs. an analyst's private instinct for what's
worth digging into), not the topic (data analysis generally).

**The wrong guess it defeats:** that asking Claude to "analyze this" means
it draws on some private sense of what's interesting in the numbers — the
kind of feel an experienced analyst has. It doesn't. The `analyze` skill
reads what kind of question you're asking — a single-metric lookup, an
investigation into what's driving a trend or drop, a comparison across
segments over time, or a formal report for stakeholders — then runs the
steps written for that shape, in order. Ask it something outside those
four shapes and it has no procedure tailored to reach for; it will not
invent a bespoke line of analysis from general analyst instinct.
