# CARRY-OUT — GATE C

Written before any other narration. Every beat exists to make this sentence
survivable.

## The line

> **Ask Claude to create a plugin, and it doesn't just write one — it walks
> five phases first, and nothing gets built until you've confirmed the
> plan.**

## The wrong guess it defeats

That asking Claude to "create a plugin" works like asking for a script or a
paragraph — one request, one finished file back. It doesn't. The skill runs
a five-phase conversation — Discovery, Component Planning, Design,
Implementation, Review & Package — and Implementation, the phase that
actually writes files, is the fourth one. Everything before it is questions
and a plan you confirm.

## The secondhand test

*If someone repeats only this sentence in a meeting next week, is it still
true?*

Yes — it compresses the one distinction that matters (a conversation with a
confirm gate, not a one-shot write) without needing a second sentence.

## What it deliberately does not say

- **Not a verdict on whether asking five phases of questions is good UX.**
  The source's B03/BVDT framed "what it gets right" / "what it bites" as a
  Teardown judgment. Plain keeps the same underlying mechanism (nothing
  written until confirmed) as a fact about sequencing, not a critique of the
  design choice.
- **Not that Claude refuses to move fast.** If the user explicitly says
  "whatever you think is best," Claude still doesn't guess silently — it
  gives a specific recommendation and still waits for a yes. The gate never
  disappears; it just changes what's being confirmed.
- **Not what a real onboarding plugin's finished files would contain.** The
  onboarding-plugin scenario is an illustrative anchor built for this reel,
  not a plan Claude has actually produced — it exists to make the five
  phases and the confirm gate visualizable, nothing more.
