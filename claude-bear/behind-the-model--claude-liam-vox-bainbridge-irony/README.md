# Why More Automation Creates More Supervision Work, Not Less

A developer hands a bug fix to her AI agent. It reads the files, edits the
code, reruns the tests, and reports back: resolved. The natural guess is that
a more capable agent means less work for the person supervising it —
capability up, workload down, one lever pulling the other. It's backwards.
Now she has to read the diff, verify the tests, check for a missed edge case,
and confirm nothing outside scope got touched — more deliberate work, not
less. This is Bainbridge's Irony, named in 1983: automation doesn't eliminate
human work, it relocates it upstream into design and into checkpoints at the
end. Watch the anchor: a naive lever where capability rises and workload
falls, then the real one where both arms rise together — and Priya, who
moves twenty files by hand alone, or reorganizes two hundred with an agent by
writing a scope, reviewing a taxonomy, approving batches, verifying counts,
and auditing spot-checks. Fewer hours. More deliberate decisions. It holds
for small, reversible tasks and flips once the agent's reach is wide, where
one wrong scope statement becomes two hundred wrong moves. More capable
agents don't reduce human work — they relocate it: upstream into the scope
you write before delegating, and into the checkpoint you run after.
