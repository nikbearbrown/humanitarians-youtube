# Claude Doesn't Design a New Zoom Chat App — It Assembles Into Yours

Someone assumes "build Zoom Team Chat App" means Claude freely designs a
brand-new chat application from imagination. It doesn't. It's a scan of
one instruction file — a SKILL.md — that Claude follows to assemble
pieces from a fixed list: user-scoped messaging integrations, chatbot
experiences, rich cards, buttons, slash commands, and chat webhooks. The
skill only switches on after something else has already routed the task
to a chat workflow, and nothing it builds becomes a new Zoom client —
every piece plugs into the Zoom Team Chat that's already running.

## YOUR TURN

"I want to add a bot to Zoom Team Chat that posts a rich card with
buttons when someone runs a slash command. Walk me through the pieces
I'd need — the message payload, the card, and the webhook — before
writing any code."

That's the whole idea: Claude assembles the pieces one instruction file
lists, into the Zoom chat you already have — it never designs a new
chat client.

## Deliberately not claimed

This reel never claims Claude designs a standalone chat application or
client — every beat keeps the boundary that every piece Claude assembles
plugs into the Zoom Team Chat that's already running. It also isn't a
claim that this replaces a developer's own Zoom API setup: the boundary
(only what the instruction file specifies, after routing to a chat
workflow) is stated as fact, not argued with.
