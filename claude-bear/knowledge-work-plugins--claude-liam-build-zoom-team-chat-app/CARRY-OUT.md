# CARRY-OUT.md

**Carry-out line:** Build Zoom Team Chat App doesn't give Claude a blank
page — it gives Claude one instruction file, and Claude assembles exactly
what that file lists (bots, cards, buttons, slash commands) into the Zoom
chat you already have.

**Wrong guess it's built to defeat:** that Claude is freely *designing* a
new chat application from imagination — architecting a client, a UI, a
product. The actual value is narrower and more mechanical: Claude reads a
fixed SKILL.md spec and *assembles* one of a bounded set of chat-surface
pieces — a bot, a rich card, a button, a slash command, a webhook — that
plug into the Zoom Team Chat that's already running. Nothing it builds
becomes a new chat client.

**Secondhand test:** "Claude doesn't design a new chat app here — it
assembles the pieces one file lists, into the chat you already have"
survives being repeated by someone who wasn't fully listening, and stays
true. It compresses the distinction that matters (assemble from a fixed
list vs. design from scratch), not the topic (Zoom integrations in
general).
