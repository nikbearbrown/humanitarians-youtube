# CARRY-OUT — GATE C

Written before any other narration. Every beat exists to make this sentence survivable.

## The line

> **A Skill is a file Claude reads before it acts, not a memory it draws
> on — the same steps, every run, and never more than what the file says.**

## The wrong guess it defeats

That running a skill like month-end-prep enough times teaches Claude
something about closing the books — the way a person gets better at a task
with practice. It doesn't work that way. There is no training step between
runs. Claude opens the same `SKILL.md` file, fresh, every single time it
executes the skill, and the file itself is the entire program: nothing
carries over, nothing accumulates, nothing hidden sits behind it.

## The secondhand test

*If someone repeats only this sentence in a meeting next week, is it still true?*

Yes — it compresses the one distinction that matters (a Skill is a file
Claude re-reads, not a capability it has acquired) into the guarantee and
the boundary that follow from it, without overstating what a SKILL.md can
do.

## What it deliberately does not say

- Not a verdict on whether month-end-prep is a well-designed skill — that's
  Teardown territory; this reel states the mechanism and stops.
- Not a claim about what month-end-prep's specific steps are. The source
  sheet's own description of this particular skill's job was never filled
  in (a template gap logged in QUESTION.md), and this reel does not
  invent business-specific close-checklist content to fill it.
- Not a claim that determinism makes the skill smart about the underlying
  business — only that the same file, run twice, produces the same
  procedure both times.
