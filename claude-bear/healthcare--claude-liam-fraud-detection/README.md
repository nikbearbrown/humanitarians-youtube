## Description

When Claude screens a pile of Medicare/Medicaid claims for fraud, does it
decide which providers committed fraud, or just flag candidates for a
person to investigate?

This is Professor Bear's Claude-basics series, narrated by Liam. Today's
worked example is `fraud-detection`, an Anthropic Claude Skill from a
healthcare compliance plugin. A Skill is a folder Claude reads before it
acts — this one has eight files: a claims schema, reference data, a file
for loading claims, one for proposing detectors, an architecture doc, a
package file, a README, and the SKILL.md itself. `fraud-detection`'s
specific job: screen a Medicare/Medicaid claims corpus for fraud, waste,
and abuse, and relay one output — a ranked list of referrals, each entry
naming the provider by NPI, the suspected scheme, the dollar exposure, and
a confidence score. It doesn't decide that fraud happened. It flags and
ranks candidates — the investigation, and the finding, stay with an SIU /
program-integrity team.

Carry-out: fraud-detection ranks and cites suspect claims for a person to
investigate — it never decides that fraud happened.
