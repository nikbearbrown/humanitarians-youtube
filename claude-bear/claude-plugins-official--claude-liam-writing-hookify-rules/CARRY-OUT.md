# CARRY-OUT — GATE C

Written before any other narration. Every beat exists to make this sentence survivable.

## The line

> **A skill fires when your words match its description — not when you name
> it. From there, Claude follows exactly what the file says, and nothing
> more.**

## The wrong guess it defeats

That switching on a Claude skill means typing its name, like a command. It
doesn't: a skill's SKILL.md carries a plain-language description near the
top, written by whoever built it, and Claude compares your own wording
against that description. Land inside it — with your own words, never the
skill's name — and it fires.

## The secondhand test

*If someone repeats only this sentence in a meeting next week, is it still true?*

Yes — it compresses the one distinction that matters (a skill fires on a
match to its description, not on being named) and it doesn't overstate what
firing guarantees: "exactly what the file says" also covers the source's own
limit — the skill only does what its SKILL.md specifies, nothing beyond it.

## What it deliberately does not say

- Not a verdict on whether the source skill's documentation should have
  demonstrated its undemonstrated behaviors more thoroughly (Teardown
  territory) — Plain states the mechanism and stops.
- Not a claim that missing the match means Claude can't help — a request
  that doesn't land inside the description simply doesn't fire this
  particular file; Claude still answers from general knowledge.
- Not a claim about *how* the matching is computed internally — only that it
  compares wording to a stated description, which is what the source's own
  description field demonstrates directly.
