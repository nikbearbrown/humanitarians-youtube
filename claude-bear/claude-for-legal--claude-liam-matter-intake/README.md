# Claude, Matter Intake — Does It Decide, or Just Log?

Pick up a skill called `matter-intake` and it's easy to hear it as a
screener: something that decides which new matters a firm should take on.
Run it on a matter with an obvious conflict and the skill doesn't refuse it
or flag it declined — it still asks the same nine questions (identification,
conflicts, source, risk, materiality, outside counsel, owners, legal hold,
key dates) and writes down the answers. Watch the anchor: those same nine
questions get planted early and return unchanged at the payoff — same order,
every matter, every lawyer. A clean run through all nine doesn't prove a
matter is conflict-free, and one flagged field doesn't prove there's a real
problem; either way, the accept-or-decline call never moves off the human.

## Deliberately not claimed

This reel names the nine intake *categories* matter-intake asks about, but
never quotes the exact question text from its SKILL.md (not reachable from
this machine) — only the categories and the two output files (`matter.md`,
`history.md`) plus the `_log.yaml` row, all carried from the source script's
own narration. It never ranks whether nine questions is the right number or
whether the file layout is well designed — that's a design judgment, and
this register states the mechanism and stops. The "obvious conflict" case is
illustrative, built to satisfy the wrong-guess beat's need for one concrete
falsifying case, not a documented test run from the source.
