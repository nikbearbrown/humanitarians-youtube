# Plan, Then Check the Plan. — The Frontend Design Skill

When you ask Claude for a landing page with a strong visual identity, the
`frontend-design` Skill runs a two-pass process before any code exists. First
pass: a design plan with four parts — color as four to six named hex values,
type as a display face plus a body face plus a utility face if needed,
layout as one-sentence descriptions and ASCII wireframes, and a signature —
the one element the page will be remembered by. Then a critique: does any
part of this plan read as the default Claude would produce for any similar
brief? If yes, it revises before writing a line of CSS. That check is what
actually catches a generic answer — it doesn't guarantee good judgment about
the subject in the first place, only that the plan isn't the same three
defaults every AI reaches for by habit.

## YOUR TURN

Paste this into Claude: Design a landing page for a handmade ceramic
studio. I want a strong visual identity — distinctive typography, a
considered palette, and one design element I won't have seen on other
ceramic studio sites. Use the frontend-design skill.

Then watch: does it name a subject and audience before choosing anything?
Does it state a palette as actual hex values? Does it tell you the
signature element before it writes any CSS? If it starts coding
immediately — no plan, no critique — the check got skipped, and that's the
tell.

---

## Deliberately not claimed

No claim about how well Claude reads the actual subject of a brief — the
critique step only checks a plan against Claude's own generic defaults, not
against whether the plan is a good fit for this specific ceramic studio,
law firm, or startup. No claim that the two-pass process guarantees a good
result; it guarantees the plan isn't a copy of what the same skill would
produce for a different, unrelated brief.
