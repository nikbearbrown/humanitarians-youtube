# CARRY-OUT — claude-for-legal--claude-liam-integration-management

**The line (written first, GATE C):**

> You can't manage an integration you're not tracking. Build the phased
> tracker, not a single plan — the plan only holds for day one.

**Test:** if someone repeats only this in a meeting next week, is it still
true? Yes — it compresses the one distinction the reel is built to land
(tracker-before-plan, updated continuously, versus a plan written once), not
the topic (post-merger integration generally).

**The wrong guess it defeats:** that the first move after closing is a
*plan* — a single document laying out what has to happen. A plan captures
one moment: the day it's written. The day after closing, several
workstreams start moving in parallel (IT systems, HR and benefits, finance
consolidation, vendor contracts), and a static document can't tell you,
six weeks in, which ones are on schedule and which have quietly stalled.
The anchor — a vendor-contract workstream marked "day-thirty" on the org
chart with no owner ever assigned — is exactly the kind of gap a plan
can't catch, because a plan is written once and never checked against what
actually happened.
