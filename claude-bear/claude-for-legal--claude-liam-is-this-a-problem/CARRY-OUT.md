# CARRY-OUT

> Is this a problem, from Claude, means is this a problem according to the
> checklist it was given — same input, same output, every run, and only
> for what that checklist thought to name.

Test: if someone repeats only this in a meeting next week, is it still
true? Yes — it compresses the actual distinction (spec-driven match, not
live judgment) without overstating what the skill covers.

**Wrong guess this defeats:** "Claude decides if this is a problem by
weighing it, the way a person would." The carry-out replaces that frame
with the correct one: the skill's `SKILL.md` is what defines "a problem"
here; Claude is checking a situation against that definition, not forming
an independent opinion about how bad it is.
