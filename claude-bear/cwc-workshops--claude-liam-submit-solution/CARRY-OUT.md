# CARRY-OUT

> Submitting a workshop solution isn't just a git task — the skill has Claude ask
> what was hardest before it commits anything, because the same PR that shows
> the code is the form that shapes the next workshop.

Test: if someone repeats only this in a meeting next week, is it still true?
Yes — it compresses both halves of the skill (the interview gate that runs
before git; the PR body that doubles as the feedback form) without
overstating either.

**Wrong guess this defeats:** "Submitting a solution is just committing and
opening a PR" (a git task, full stop). It misses that Step 1 — three
questions, asked before Claude touches git at all — is not optional color;
the PR body template has a whole "Workshop feedback" section, and that
section is why the questions get asked first instead of being folded into
a commit message afterward.
