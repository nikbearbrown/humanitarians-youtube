# CARRY-OUT — GATE C

Written before any other narration. Every beat exists to make this sentence survivable.

## The line

> **Getting the right answer to the wrong problem is still getting it
> wrong. Reframe the problem before you trust the answer.**

(Compressed from the source's Type III definition and B07 summary —
"the AI solved the problem you stated, and the problem you stated was
wrong" / "the reframing test does not guarantee you found the right
problem; it guarantees the reframings are actually different from each
other" — restated in Plain register. It states the mechanism and its
limit, not a design verdict, so nothing needed removing.)

## The wrong guess it defeats

That an answer is good if it satisfies the problem exactly as asked. That's
backwards for anything an AI can get technically right while still missing
the point: asked to cut support-ticket volume, "hide the contact button"
does cut the count — the ask is satisfied — while the reason people needed
help in the first place goes untouched. Checking the answer against the one
way you happened to state the problem can't catch that; you have to state
the problem more than one honest way and see whether the same answer
survives all of them.

## The secondhand test

*If someone repeats only this sentence in a meeting next week, is it still true?*

Yes — it compresses the one distinction that matters (correct-for-the-stated-
problem vs. correct-for-the-real-one) without claiming every answer needs
reframing or that a single test proves anything.

## What it deliberately does not say

- Not a claim that answers which diverge across framings are proven right —
  divergence only proves the framings were genuinely different questions;
  which one to act on is still a judgment call (direction A, B05).
- Not a claim that answers which collapse into one framing are worthless or
  that no better answer exists — collapse is the signal to add another
  framing, not a dead end (direction B, B06).
- Not an accusation that anyone asks bad questions on purpose. Trusting a
  technically-satisfying answer is an ordinary, reasonable-sounding habit,
  and the reel treats it as one.
