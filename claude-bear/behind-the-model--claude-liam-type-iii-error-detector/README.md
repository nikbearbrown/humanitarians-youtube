## Title

Type III Error Detector — When Claude's Answer Is Right and the Problem Is Wrong

## Description

Ask Claude to cut support-ticket volume, and one answer comes back fast: hide
the contact button. The ticket count really does drop. The ask is
technically satisfied — and completely wrong, because nothing about why
people needed help got fixed. Statistician Howard Raiffa had a name for
solving the wrong problem correctly: a Type III error. AI is particularly
good at making them, because it optimizes the objective you wrote down, not
the one you meant.

From Humanitarians AI: short, plain explanations of how Claude actually
works, for a general audience meeting Claude for the first time. Liam, in
for Professor Bear.

In this one: the natural check — does the answer satisfy what I asked? —
and the case that breaks it; the reframing test, which states a problem
several honest ways and tests each candidate answer against every framing;
what it means when an answer collapses every framing into one (the warning
sign); what it means when answers genuinely diverge (not proof you found the
right problem, just proof the framings were real); and the fix when
everything collapses — add another framing and keep going.

Try it yourself — the video ends with a paste-ready prompt for running the
reframing test on your own problem statement.
