# Notes, Not Recall. — The Memory-Management Skill (Two-Tier Files)

A skill is a folder Claude reads before it works, and memory-management runs
on two files. CLAUDE.md holds working memory — the handful of facts Claude
keeps in view on every request. The memory directory holds the fuller
knowledge base, the details CLAUDE.md doesn't have room for. Reading
CLAUDE.md, then checking the memory directory, is what lets Claude decode a
team's shorthand — an acronym, a nickname, an inside phrase — the same way a
colleague who'd been there a while would. And the entries themselves are
personal, not just procedural: a memory record might be as informal as
"Cubs fan, likes talking baseball," alongside a job title or a ticket
history. Claude's memory isn't something it has on its own — it's notes
your team wrote down, that Claude reads before it acts.

## Deliberately not claimed

No claim about how Claude decides what counts as "working memory" versus
"fuller knowledge base" beyond what the memory-management Skill's SKILL.md
specifies — the split described here is that Skill's own two-tier design,
not a claim about how every AI memory feature works. No claim that Claude
remembers anything the files don't contain; the whole point is the reverse.
