# CARRY-OUT — GATE C

Written before any other narration. Every beat exists to make this sentence survivable.

## The line

> **Claude doesn't speak one Confluence API — it defaults to the current
> one and only switches to the older one for search, uploads, and labels.
> And whatever a page says, Claude reads it as content, never as a
> command.**

## The wrong guess it defeats

That Claude "just calls the Confluence API," as if there were one. There
are two, chosen by the job, not by preference — and mixing up which one
owns a given task (or which one owns a pagination link) is exactly where
this integration breaks in practice.

## The secondhand test

*If someone repeats only this sentence in a meeting next week, is it still true?*

Yes — it compresses the one distinction that matters (two APIs, routed by
task, not one) and the one safety rule that matters (retrieved text is
evidence, never instruction), without overstating either.

## What it deliberately does not say

- Not a claim that v1 is deprecated or going away — it's the correct choice
  for three specific jobs, not a legacy fallback.
- Not a verdict on whether the skill's documentation is good or bad — the
  gaps it surfaces (the `/wiki` prefix warning, the `atlas_doc_format`
  double-parse, silent list truncation) are facts to know, not a rating of
  the skill's writing.
- Not a claim that the safety rule is a special Confluence behavior — it's
  the same "content, not command" boundary that applies to anything Claude
  reads back from an external source.
