# How Does Claude Build a Due Diligence Checklist?

Ask Claude to build a due diligence checklist and it's tempting to picture
it sizing up your specific deal and deciding, from its own judgment, which
risks are worth chasing. That's not what's happening. Anthropic's
`dd-checklist` skill reads a written SKILL.md and builds the checklist from
workstreams the file already defines, tailored to the target's sector, deal
type, and complexity — nothing more. Watch the anchor: a software company
acquisition. "Customer contracts" goes out as a request, comes back
received, gets reviewed — and one clause, heavy revenue concentration in a
single customer, gets flagged as a red flag for the deal team. Run that same
checklist twice and the workstreams come back identical. Ask for a deal
type the file never described — a mineral rights transfer, say — and
there's nothing tailored to reach for. A Claude due diligence checklist is
a written procedure tailored to the deal's sector and type — not Claude's
independent judgment about what you owe scrutiny.

## YOUR TURN

"Give me a deal profile — say, a software company acquisition — and run
the dd-checklist skill: build the workstreams, the request lists inside
each one, and where red-flag escalation would trigger. Then ask for a
sector or deal type you've never mentioned supporting."

Watching whether Claude invents a bespoke workstream for an unsupported
deal type, or tells you plainly that it has nothing tailored for it, is the
fastest way to see that the checklist tailors from a written file rather
than independent judgment — rather than just trusting that it does.

## Deliberately not claimed

This reel redoes a published Teardown-register skill-showcase reel
(`claude-liam-dd-checklist`) in the Plain register for a general audience.
The underlying facts are unchanged from the source: the skill generates and
tracks due diligence checklists tailored to the target's sector, deal type,
and complexity, covering major workstreams with request lists, status
tracking, and red-flag escalation — it does not exercise independent
judgment about which risks matter for a specific deal beyond what the file
and your inputs already define. This script makes no claim about specific
deal terms, tools, or UI — only the general mechanism (a written procedure
that tailors known workstreams) and its two failure directions.
