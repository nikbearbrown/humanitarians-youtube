# CARRY-OUT — GATE C

Written before any other narration. Every beat exists to make this sentence survivable.

## The line

> **A change reported after it happens is an audit log. A change confirmed
> before it happens is supervision — and only supervision can still change
> what happens.**

(Compressed from the source's B03/B04 claim — "reporting a scope change
after the action is an audit log. Asking before the action is supervision.
Only before catches the error" — restated in Plain register. It states
mechanism, not a design verdict, so nothing needed removing.)

## The wrong guess it defeats

That an agent adapting mid-task is fine as long as it explains itself
afterward — a completion report listing what it had to do differently.
That's backwards for any change that crosses a real boundary: a different
tool than the one approved, data beyond what was named, or a higher risk
level than the plan described. By the time a report exists, the library is
already installed, the folder is already read, the output is already sitting
in a shared destination someone else can reach. None of that undoes by being
described after the fact. The check has to sit before the step, not after
it.

## The secondhand test

*If someone repeats only this sentence in a meeting next week, is it still true?*

Yes — it compresses the one distinction that matters (supervision vs. audit)
without claiming every adaptation needs a pause or that a report after the
fact is worthless.

## What it deliberately does not say

- Not a claim that every agent adaptation needs a confirmation pause —
  routine, in-scope adaptations (a retried tool call, reading the one file
  it was told to read) keep going without one (source B01, direction A).
- Not a claim that a report after the fact has no value — it still tells you
  what happened, which is useful even though it can't be undone (direction
  B).
- Not an accusation that adapting mid-task is itself a failure — adaptation
  is a normal feature of how these agents work, not an error (source B01).
