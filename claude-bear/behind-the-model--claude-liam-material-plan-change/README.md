## Description

An agent that adapts mid-task isn't misbehaving — a tool failing, a file going missing, a
format coming in wrong are ordinary parts of how these systems work. The natural fix is to
let it keep going and read a report afterward. But by the time that report exists, the
library is already installed and the shared folder is already read — changes nobody
approved. Three signs mark a change worth stopping for: a different tool than the one
approved, data beyond what was named, or a risk level higher than the plan described. Catch
any one of them, and the question is only where the check sits: a report written after the
fact is an audit log; a question asked before the step is supervision, and only supervision
can still change what happens.

From Humanitarians AI: short, plain explanations of how Claude actually works, for a
general audience meeting Claude for the first time. Liam, in for Professor Bear.

In this one: the natural shortcut of letting an agent report scope changes after finishing;
why that report can't undo anything; the three-trigger rule for stopping before the next
step; a five-step plan (planted early, paid off late) that shows the same adaptation two
ways — paused for approval, or already done and only logged; and the failure mode on the
other side, where stopping for every small adaptation gets waved through unread.

Try it yourself — the video ends with a paste-ready prompt for building a material-plan-
change detector into your own agent workflow.
