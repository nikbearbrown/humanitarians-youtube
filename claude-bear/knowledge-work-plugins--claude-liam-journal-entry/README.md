# By File, Not By Feel. — The Journal-Entry Skill (Debits & Credits)

A Skill is a folder Claude reads before it works — this one is journal-entry.
Its SKILL.md holds the full instruction set, in plain language, with no
hidden logic and no accounting judgment baked in: Claude reads the file,
then acts exactly on what's written. The steps live in the SKILL.md's Steps
section, in order, and Claude executes them top to bottom — no branching,
no judgment calls, unless the step itself says so. That's the deliberate
trade: journal-entry is a specification, not expertise. The same request
produces the same debits, credits, and supporting detail, every single
run — but anything outside what the file actually specifies, Claude has no
basis for deciding on its own.

## Deliberately not claimed

No claim about Claude's general accounting competence outside a Skill file
— the video is specifically about what changes when a journal-entry Skill
is installed, not a claim about what Claude can or can't reason about
unaided. No claim that a specification-driven Skill is a worse design than
judgment-driven reasoning would be; the video states the trade (repeatable
inside the spec, no basis outside it) without ranking it against an
alternative.
