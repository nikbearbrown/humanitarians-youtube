# CARRY-OUT (written before any narration — GATE C)

**The line:**

> Data visualization doesn't start with a bright palette — it starts with
> the chart type the data's relationship calls for, and color only earns a
> place once it carries meaning.

**Secondhand test:** if someone repeats only this in a meeting next week —
"Claude picks the chart type first, then earns the color" — is it still
true? Yes: it names the two-step order (chart type from the data's
relationship, then color as a meaning-carrying constraint) without
overstating either half.

**The wrong guess it defeats:** "data visualization" sounds like it's about
making a chart colorful or visually appealing. It corrects to: color is a
constraint that has to earn its place (it encodes a finding, it has to
survive without being seen at all by someone colorblind), and it is applied
*after* the chart type has already been chosen from what the data is doing
— never before, and never as decoration.

**Why this line, not the source's verdict:** the source's closing beat
(`BVDT`) graded the skill ("What it gets right: repeatable results. What it
bites: anything outside the spec.") — Teardown judgment, not a Plain
carry-out. This line states the mechanism's actual order of operations
instead, which is what survives repetition without becoming a verdict on
whether the skill is well-designed.
