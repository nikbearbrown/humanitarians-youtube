## Deliberately not claimed

- **Not "Claude customizes itself."** The naive framing in B00 ("customize itself
  for you") is stated and corrected within the same beat — the skill shapes ONE
  task's output to a written spec; it never changes Claude's general behavior,
  personality, or settings.
- **Not a claim about what `customize` specifically formats.** The source's own
  narration never filled in what the skill customizes (see QUESTION.md — every
  sibling in this batch carries the same unresolved `>` placeholder). This script
  states only the generic, true mechanism of how any Skill folder works, using
  `customize` solely as the example skill's name — it does not invent a specific
  document type, house style, or product feature the source never specified.
- **No verdict on the skill's design.** The source's Teardown register judged the
  skill ("what it gets right," "what it bites"); this Plain redo describes the
  same constraint without ruling on whether it was well designed.

## Handoff prompt (BHTF, read aloud)

> "Read the customize skill in this folder, tell me exactly what it will change
> about my output before you touch anything, then apply it once so I can check
> the result against the spec."

Why it's worth running: it forces Claude to state its own scope before acting —
the same "explain first" clause the source reel's own handoff used to surface a
skill's real constraint logic.
