## Plate work order

All six written by `python -I assets/gen_craters.py` into `assets/plots/`.
Seeded, asserted, deterministic. Plates carry **imagery only** — no text, no
ticks, no legend — because a plate arrives in Manim as an `ImageMobject` and
GATE B is nearly blind to its interior. Every label is placed by `scenes.py`
*outside* the plate.

| plate | what it draws | used by |
|---|---|---|
| `surface.png` | two patches of ground, 14 craters vs 80 | B03 |
| `pile.png` | three populations on a log axis **with decade rails** | B04 |
| `spread.png` | one patch; filled = unanimous, open = contested | B05 |
| `curve.png` | the Neukum chronology function, log N(1) vs age | B07 |
| `cost.png` | the ±45% band through the curve, **plus the relative panel** | B08 |

## Build order

1. `python -I assets/gen_craters.py` — asserts nine claims, writes six plates
2. `generate_audio_kokoro.py` — measured MP3s become the master clock
3. pin `durationInSeconds` on B00/B11/B12/B13 from the **measured** audio
4. solve pacing into `scenes.py` (`BEAT`, `RT`, `HOLD`, `RT_PORTRAIT` if needed)
5. `bash runtime/scripts/run.sh <reel> --height 2160` — GATE F/L/A/W → render → GATE B → compile → GATE V
6. repeat 3–5 for the 9:16 cut in `short/`
7. read frames at native 4K; log in `VISUAL-QC.md`

## Aspect

Both cuts are authored, not cropped. `scenes.py` is aspect-aware (`P()` picks
landscape/portrait values); the Remotion beats use their `*916` compositions,
which **reuse the same zod schema** — so one prop audit covers both.

Set `metadata.aspect_ratio` **after** any Remotion run and verify it before
compiling: `remotion_scenes.py` restamps `beat_sheet.json` from a copy it
loaded at start, which has silently reverted that field before.
